## LawFirm OS flagship architecture

LawFirm OS is the main public flagship architecture. It is not a single chatbot repo. It is a multi-repo operating architecture for legal AI governance.

| Plane | Repo | What it owns | What it must not do |
|---|---|---|---|
| **Control plane** | [`LawFirm-os-semantic-substrate`](https://github.com/lowelltwong-alt/LawFirm-os-semantic-substrate) | Canonical schemas, registries, governance docs, route/event authority, manifest authority, autonomy/harness/research policy. | Execute runtime behavior or store real client/matter data. |
| **Execution plane** | [`LawFirm-os-orchestrator`](https://github.com/lowelltwong-alt/LawFirm-os-orchestrator) | Contract-locked orchestration, autonomy classification, harness selection, evidence packet preparation, local synthetic workflows. | Define canon, invent route IDs, or treat runtime output as truth. |
| **Evidence plane** | [`LawFirm-os-exceptions-lake-runtime`](https://github.com/lowelltwong-alt/LawFirm-os-exceptions-lake-runtime) | Append-only runtime records, audit evidence, synthetic exception intake, validation outcomes. | Mutate canon or promote runtime evidence into authority. |
| **Legal knowledge runtime** | [`LawFirm-os-legal-knowledge-runtime`](https://github.com/lowelltwong-alt/LawFirm-os-legal-knowledge-runtime) | Synthetic legal ingestion preflight, retrieval planning, Legal Context Bundle assembly. | Store real legal payloads or provide legal finality without human review. |
| **Skills / trust plane** | [`LawFirm-os-skills-registry`](https://github.com/lowelltwong-alt/LawFirm-os-skills-registry) | Skill discovery, quarantine, scanning, grading, skill trust records, draft skill generation. | Let imported skills become backdoors or shadow sources of truth. |

Core operating law:

```text
Risk color controls authority.
Hardness controls harness depth.
Leverage controls priority.
Stakes size controls escalation sensitivity.
Reversibility controls autonomy.
Frequency controls compounding value.
```

## What is different about this architecture

Most AI projects start with a model, tool, or workflow. These repos start with **authority discipline**.

| Typical build | This architecture |
|---|---|
| Prompt-first | Registry / schema / governance-first |
| Agent improvises authority | AI routes through front doors and authority maps |
| Single repo claims everything | Separate control, execution, evidence, knowledge, and skills planes |
| Runtime logs become “truth” | Runtime evidence remains evidence until governed promotion |
| Roadmap is feature list | Roadmap is an authority-gated upgrade path |
| AI reads README and guesses | AI reads deterministic TOCs, registries, boundaries, endpoint maps, and update instructions |
