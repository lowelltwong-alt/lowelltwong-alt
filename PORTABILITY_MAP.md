# Portability Map

The public work uses legal operations and theological knowledge architecture as reference domains. The transferable pattern is not a claim of cross-domain deployment: it is the design discipline of separating source authority, validation, evidence, execution, and review.

| Reference-domain concern | Portable pattern | Public evidence class |
|---|---|---|
| Contract and policy authority | Explicit schemas, controlled vocabulary, and change boundaries | LawFirm OS public contract |
| Messy intake material | Synthetic, human-reviewable staged workflow | LawFirm OS Intake implementation |
| Runtime exceptions | Append-only evidence distinct from canonical truth | Exceptions Lake implementation |
| Source interpretation | Provenance, boundaries, and human-accountable review | Logos public architecture |
| Note maintenance | Local graph analysis and review candidates | Orphan Radar public implementation |
| Copilot and reusable-asset integration | Manual agent handoffs plus a typed Mini-DAD graph, local MCP, guarded HTTP, and lifecycle gates | Albert Copilot Studio Design public reference; source-owned Mini-DAD implementation |

## Boundaries on portability

- The public materials do not demonstrate production deployment, measured business value, real-data validation, or model superiority.
- Deterministic validation is evidenced for Intake, Logos Scripture Graph, Orchestrator, and Skills Registry.
- Orphan Radar's bounded stochastic candidate ranking is classical graph/TF-IDF calibration, not LLM evaluation.
- DAD is private by request and is not evidence of a deployed headless service or execution authority.
- Albert Copilot Studio Design does not establish tenant acceptance, Azure deployment, a complete Albert backend, or automatic agent/lesson promotion.

See `registry/portfolio-capability-evidence.json` for claim-level status and pinned source evidence.
